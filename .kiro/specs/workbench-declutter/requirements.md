# Workbench declutter: Task 78

Additive specification, 2026-11-09. Owner feedback: "the main menu is way too cluttered, it's hard to follow where the instructions are and where to go. There are just too many words. Incorporate popups for the guided activities and try to hide as much additional information in dropdowns." Applies to all ten available challenges. Presentation only: no physics, evaluation, challenge JSON, reducer, guided-plan or persistence change. The decision record is D-65 (written by the director). Where this spec and D-48's amendment (visible challenge paragraph) differ, the lead sentences stay visible and only the remainder collapses (WD-04).

## Visibility rules

- WD-01: Always visible in the workbench: the lead of the challenge statement (at most two sentences), the checks list (VALUE / LIMIT), the design controls, the primary design view, Run Test, the result status, model warnings, not-applicable reasons, and the model-limits footer notice (MVP Req 29.7, unchanged wording and placement).
- WD-02: Collapsed by default, inside the shared `Disclosure`: the remainder of the challenge statement, explanatory paragraphs, secondary charts and diagrams, long captions, model notes, formulas, and tables that duplicate the checks. Nothing is deleted or reworded; it is moved. Information needed for correctness or honesty about model limits (D-48) stays in the DOM and reachable by one click and by keyboard.
- WD-03: "About this model" is one collapsed Disclosure in the workbench chrome holding the tagline, the solver label, the model's `contextNote` and the mode sentence. Parametric's explanatory sentence is in the same Disclosure. The library and the challenge drawer keep their own mode sentences.
- WD-04: `ChallengeStatement` shows the first `leadSentences` (default 2) sentences as a visible paragraph and the rest, word for word and in order, in a Disclosure named "More about this challenge". With nothing left there is no Disclosure. Sentence splitting is deterministic and does not break at decimals ("4.0 MPa"), unit text ("Ø24.5 mm") or abbreviations ("i.e.", "e.g.", "approx.", "vs.").
- WD-05 [AMENDED by task 78.4: the chip is gone (78.3) and the non-modal popover is a modal step dialog, WD-40 to WD-47]: Guided instructions are not inline. A compact chip "Step N of M: <title>" is always visible; a non-modal popover shows the step instruction, the experiments list, the "Editable now" line, the hint (inside a Disclosure) and the latest step feedback.
- WD-06: Disclosure state and popover state are UI state only: never persisted, never in the reducer, never announced.

## Popover behaviour and accessibility

- WD-10 [SUPERSEDED by WD-40 to WD-42, task 78.4; kept for history]: The popover opens automatically on first entry and whenever the current step (or the latest not-yet-met attempt) changes, without moving focus. Focus is never trapped; the design controls stay operable while it is open.
- WD-11 [SUPERSEDED by WD-41, task 78.4; kept for history]: Escape and the Close button dismiss it. Focus returns to the chip only when focus was inside the popover. Escape pressed elsewhere dismisses an open popover without moving focus. The chip toggles it (`aria-expanded`, `aria-controls`).
- WD-12 [SUPERSEDED by WD-40, task 78.4; kept for history]: The popover is `role="group"` with an accessible name (not a dialog, because it is non-modal and must not appear in the dialog tree); it adds no live region. Step changes are announced only through the existing `ui/a11y/LiveRegion` text (MODE-07). When open it adds at most three tab stops in total (chip, Close, hint summary).
- WD-13 [SUPERSEDED by WD-47, task 78.4; kept for history]: No overlay on the 3D canvas (D-26). Above 870 px it hangs under the chip over the challenge column; at 870 px and narrower it renders in flow under the chip, so it never covers the design view, the Run Test button or the controls. No inline styles (CSP).
- WD-14: Locked controls show one line near the chip instead of one sentence per control. Each locked control keeps its read-only or disabled state, a small lock icon, and an `aria-describedby` target with the reason, so the lock is never conveyed by colour alone. The reducer's locked-edit rejection and announcement are unchanged.
- WD-15: Every control keeps an accessible name, layout works at 320 px, and serious/critical axe gates hold.

## Shared building blocks

- `ui/workbench/Disclosure.tsx`: `<Disclosure summary id? defaultOpen? className?>`; native `<details class="ei-disclosure">`; closing returns the layout to its height (e2e/disclosure.spec.ts).
- `ui/workbench/ChallengeStatement.tsx` with `splitStatement(text, leadSentences)`.
- `ui/workbench/GuidedStepPopover.tsx` mounted by `ModeExperience`.
- `ui/workbench/LockNote.tsx`: the per-control lock mark.
- Each model's CSS lives in `ui/models/<model>/<model>.css`, imported by that model's entry.

## Per-model checklist (one worker per model; touch only that model's files)

1. Challenge panel: replace the statement paragraph with `<ChallengeStatement text={...} />`; keep the checks list, applicability reasons, warnings, Run Test and the reference link visible.
2. Wrap the explanatory paragraphs, long captions, model notes and secondary charts/diagrams of the view in `<Disclosure>`; migrate that model's own `<details>` ("Some things are fixed.", sections tables, etc.) to `Disclosure` only if the visible text and e2e names stay accurate. Keep the text equivalents of charts (MM-22) and the `*_SUMMARY_ID` description targets in the DOM.
3. Keep the model's limits notice (`copy.limitsNotice`) unchanged; do not move or shorten it.
4. Do not edit `evaluation/guided/*`, `state/*`, challenge JSON, the shared workbench files, or tracking documents; model CSS goes in the model's own css file.
5. Update that model's unit and e2e specs: text that moved into a Disclosure is asserted after opening it (same strength); the Parametric sentence now lives in "About this model" (use `openAbout` in `e2e/helpers.ts`); Guided heading assertions use `expectGuidedStep`.
6. Run lint, typecheck, the model's vitest files, the model's Playwright spec on both projects, and axe.

WD-01 and WD-04 are amended as stated here: the visible statement is the card goal line plus the first sentence (was the first two sentences in the right-hand column).

- WD-20: A full-width challenge band is the first workbench content in DOM order, directly after the page title row and before "About this model", the Guided chip and lock line, the design tools and the design view. It has one `h2` "The challenge" and is a labelled region.
- WD-21: The band holds, in order: (a) a one-line goal headline, which is the challenge's library card summary line from `challenge/catalog.ts` (the existing `description` field, not new wording); (b) the first sentence of `challenge.statement` as a visible paragraph (`ChallengeStatement` with `leadSentences={1}`); (c) the rest of the statement, word for word and in order, in the collapsed "More about this challenge" Disclosure (none when nothing is left). When the headline and first sentence are near-identical for a challenge, both still show.

- WD-24: No challenge JSON, catalog text, physics, evaluation, reducer, guided-plan or persistence change, so no content version bump (MM-04). The model-limit sentences in statements (D-48) stay in the DOM, reachable by one click and by keyboard.

## Task 78.4: the Guided step instruction is a modal dialog (owner, 2026-11-10)

Owner, after seeing the stepper preview: "The 'Grow the circle' popup should be a popup that takes over the screen and must be read and then closed. It can then be reopened by clicking on the 'Grow the circle' text." Presentation only. WD-10 to WD-13, WD-31 and WD-32 (the non-modal popover and its in-flow placement) are superseded by WD-40 to WD-47; the stepper itself (WD-30, WD-33 to WD-36) is unchanged except as stated.

- WD-40: Guided only: the current step's instruction is a modal dialog built on the shared `ui/dialogs/Dialog` (body portal, `role="dialog"`, `aria-modal="true"`, centered over a dimmed backdrop covering the whole app, focus trap, Escape). Its accessible name is "Step N of M: <step title>" (with every step met, "All N steps complete"). Content in order: the step title as the heading, the instruction, "Editable now: <focus>", the lock line, the Hint inside a collapsed `Disclosure`, the step feedback line when there is one, and a primary button "Got it". The dialog's standard "Close" (x) button is kept. A click on the backdrop does not dismiss it: it must be read and closed with "Got it", Close or Escape.
- WD-41: Initial focus follows `Dialog` (its first focusable element, the Close button, as in every other dialog). Closing by "Got it", Close or Escape returns focus to the current step button in the stepper (to the "All N steps complete" button when every step is met). Focus is trapped while it is open and the page behind is not reachable by keyboard or pointer.
- WD-42: It opens automatically (a) on entering a challenge in Guided, including reload and resume, and (b) whenever the current step changes: a new step begins, or all steps complete (the completion message is shown once). It does not open after a test attempt that fails to meet the current step.
- WD-43: Step feedback after an attempt that did not meet the current step (the existing text "Iteration N did not complete this step yet. Change only <focus> as asked, then Run Test.") shows as one short line directly under the stepper row and also inside the dialog when reopened. The line is absent when there is no feedback. It has no live region of its own; nothing new is announced.
- WD-44: The current step in the stepper (the button showing the step name; "All N steps complete" when finished) opens the dialog and has `aria-haspopup="dialog"`. `aria-expanded` and `aria-controls` no longer apply and are removed. Completed and future steps are not buttons. The row adds one tab stop.
- WD-45: Only one dialog at a time. The step dialog never opens on top of another dialog (Prediction, submit, import error, reference or help dialogs); if one is open when the step dialog is due, it is queued and opens when the other closes. The Run Test to Prediction dialog flow is unchanged and the step dialog reuses none of the other dialogs' button names ("Run structural test", "Back to design" and so on).
- WD-46: Nothing is pushed down: the dialog is not in flow, so with it closed the workbench sits at the same vertical position as in Parametric apart from the stepper row itself (and the one feedback line when present). The old popover markup and CSS, including the narrow-width in-flow variant, are removed.
- WD-47: A modal dialog over the whole app is the same class as the Prediction dialog and is not an overlay on the 3D model, so D-26 is not engaged. Parametric has no stepper and no dialog. No inline styles, no new live region, no step derivation, lock, reducer, JSON or wording change.

## Task 78.5: step dialog formatting, open delay and About row gap (owner, 2026-11-10)

Owner, after seeing the step dialog: "formatting looks a little messed up. Also, give some delay before showing the popup." And, after seeing the bottom of the workbench: "give some more gap between the two boxes". Presentation and timing only; WD-40 to WD-47 stand except where amended here (the separate lock line of WD-40 is merged into the "Editable now" line; the immediate opening of WD-42 becomes a delayed opening).

- WD-48: The step dialog body is one text block: every body paragraph has the same font size and line height, the blocks (instruction, editable line, Hint, feedback or result line) are separated by one consistent gap, and they share a single left edge. "Editable now: <focus>. Other parameters stay locked until a later step." is ONE line with the lock icon (`aria-hidden`) inline at its start, aligned to the first text line; the separate "Locked in this step: everything except <focus>. Others unlock in later steps." paragraph is not in the dialog (no new wording). When nothing is locked (final step) the line has no icon. The per-control lock marks and their screen-reader reasons are unchanged. The Hint row sits on the same left edge with its chevron at the right edge and the same body size when opened. The completion dialog and a dialog with a feedback line follow the same rhythm; no overflow at 390 px.
- WD-49: Above the "Guided mode / About this model" row (`.workspace-context`) is the same vertical gap the page uses between the workbench row and the results panel (19 px), in Guided and Parametric and at narrow widths; the gap below it, above the limits footer, is also at least 12 px. E2E asserts at least 12 px above and below.
- WD-50: The dialog opens after a delay, not at once. On entering a Guided challenge (the host becoming visible, including reload and resume) the delay is `STEP_DIALOG_ENTRY_DELAY_MS` = 800 ms; when a new step begins (a step is met, or all steps complete) it is `STEP_DIALOG_STEP_DELAY_MS` = 1500 ms, so the test result is seen first. Clicking the current step name (or "All N steps complete") opens it immediately and cancels the pending timer.
- WD-51: The timer is cancellable: it is cleared on unmount, when the host is hidden again, and when the step changes again (which restarts the wait). If another dialog is open when it fires, WD-45 queueing applies. If the student interacts during the delay (edits a control, presses Run Test) the dialog still opens after the delay unless another dialog is open. During the delay the page is fully usable and nothing is focus-trapped; when the dialog opens, initial focus and focus return are as WD-41. `prefers-reduced-motion` governs only a fade animation, never the delay; there is no fade. No inline styles.
