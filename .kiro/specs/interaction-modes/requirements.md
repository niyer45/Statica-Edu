# Guided and Parametric interaction modes — task 44.1

Additive specification, 2026-10-16. Applies now to the available Cantilever Beam I; future available challenges reuse only compatible content/contracts. Does not activate Beam II or Freeform, change physics, or regenerate completed MVP requirements. User explicitly selected task 44 ahead of catalog scoping.

- MODE-01: Guided shows the existing workflow stepper plus a compact instruction panel outside the challenge panel and Canvas. Four browsable steps: Inspect, Experiment, Compare and Explain. Each shows one concise instruction; optional hints/suggested experiments are collapsed by default. Do not duplicate evaluation tables or add static model overlays.
- MODE-02: Recommend Inspect for a Baseline-only tested workspace, Experiment for an untested draft, Compare once a visible non-Baseline test exists, and Explain when reflection/submission exist (draft takes precedence over unfinished reflection). Recommendations derive from stored state, not claimed student mastery. Browsing a step never creates tests, scores, submission or completion; users may visit steps in any order. Re-derive recommendation after a relevant session change or reload; browsing selection/hint disclosure are transient UI state.
- MODE-03: Guided instructions refer to the actual challenge statement/fixed values, existing editing tools, prediction/test/compare/restore/reflection actions and model limits. Hints use applicable section concepts: rectangle/I orientation versus round-section diameter/wall or material-placement experiments. Never reveal internal referenceDesign or invent numerical results. Hints suggest observation, not a guaranteed passing solution.
- MODE-04: Parametric shows the same supported section presets, numeric dimensions, orientation, visual handles, constraints, Run Test, history/comparison, reflection/submission, help and fallback; omit the Guided panel and instructional workflow stepper. Display a short direct-edit description. Maintain challenge-configured prediction checkpoints in both modes.
- MODE-05: Choose Guided/Parametric in the existing library/challenge-entry screen before opening. The active workbench exposes no mode select, toggle or switching action. Its mode is fixed for that entry. Existing shell entry calls store.selectMode; returning to the library permits a new entry choice, while ordinary resume retains the saved mode. Do not add a permanent account/project lock or reset the workspace to enforce this UI requirement.
- MODE-06: Reload/resume retains persisted session.mode and draft/errors, immutable history/deletion metadata, comparison, predictions, reflection, submission and latest-tested deformation. Existing editor/state/solver/save schema stay unchanged. A new entry selection preserves the shared challenge workspace; guidance browsing is transient and rederives focus from stored state. Existing numerical input blur behavior is unchanged.
- MODE-07: All guidance and pre-entry mode controls are keyboard-operable, have visible focus, wrap at 320 px, and retain serious/critical axe gates. SVG fallback offers the same mode distinction and editable tools. The instruction panel must not create another live region; announcements use the existing channel.
- MODE-08: Verify distinct presentation, browsing/hints with no session effects, seeded draft/history/reflection/submission/deletion preservation, persistence reload, pre-entry allowed-mode gating and identical solver outputs for identical action sequences in both modes. Include desktop/mobile keyboard entry, absence of workbench mode controls and fallback browser checks. CI evidence is distinct from owner manual release QA.
